# Safarancho Pager — архитектура mesh-сети

Документ описывает, как устроена децентрализованная доставка сообщений
после доработки до полноценного mesh-мессенджера, и что ещё предстоит.

## Идея

Сообщение должно найти получателя по любому доступному пути:
**интернет → Wi-Fi (LAN) → BLE (phone-to-phone)**. Каждое устройство и
каждая серверная нода — равноправный узел, который умеет принимать,
доставлять локально и **ретранслировать** чужие сообщения дальше.

## Единый конверт сообщения

Один и тот же формат на бэкенде (`backend/mesh_router.py::MeshMessage`) и
в Android (`mesh/MeshEnvelope.kt`):

| Поле | Назначение |
|------|-----------|
| `msg_id` | 128-битный id — дедупликация и обратный маршрут |
| `from_ss` / `target_ss` | отправитель / получатель (SSID) |
| `text` / `kind` | полезная нагрузка и тип (text/file/ack) |
| `ttl` | счётчик хопов, ограничивает флуд |
| `path` | список пройденных нод — защита от петель |

## Маршрутизация (ядро)

`MeshRouter` — чистая логика без I/O, поэтому покрыта юнит-тестами:

1. **Дедуп** по `msg_id` (TTL-кэш `SeenCache`, ограничен по памяти).
2. **TTL**: на нуле сообщение больше не пересылается (но всё ещё
   доставляется локально, если адресовано нам).
3. **Loop avoidance**: не пересылаем ноде, уже бывшей в `path`.
4. **Directed routing**: если известно, какой сосед достаёт до
   `target_ss` (выучено из `/mesh/hello`), шлём прицельно; иначе
   **флуд** по всем непосещённым соседям.

## Транспорты

### Бэкенд (нода)
- `POST /mesh/ingest` — **единая точка входа для любого транспорта**.
  Принимает конверт, прогоняет через router, доставляет/пересылает.
- `POST /mesh/hello` — обмен контактами и URL соседей (теперь учит
  реальный `self_url`).
- `POST /mesh/deliver` — legacy single-hop, заворачивается в тот же путь.
- **Store-and-forward**: сообщение офлайн-получателю сохраняется
  (`messages.delivered=0`) и досылается при подключении по WebSocket.

### Android (узел)
- `Transport` — общий интерфейс. Реализации:
  - `InternetTransport` — HTTP на `/mesh/ingest`.
  - `WifiTransport` — NSD/mDNS (`_pagermesh._tcp`) обнаружение пиров в
    LAN и доставка по HTTP без интернета.
  - `BleTransport` — GATT-реле: устройство одновременно сервер
    (рекламирует сервис) и центральный (сканирует, пишет). Чанкинг
    конвертов под лимиты BLE через `ChunkAssembler`.
- `MeshManager` — рассылает по всем доступным транспортам, дедупит
  локально, ретранслирует чужое (TTL--), отдаёт своё в UI.

## Видеозвонки (сделано)

WebRTC «точка-точка», сигналинг поверх существующего WebSocket
(`type=call_signal`: offer/answer/ICE/end), медиа идёт P2P. Сервер
только сводит стороны (`server.py`, ветка `call_signal` в `/ws`).
Совместимо между веб-клиентом и Android:

- **Веб** (`index.html`): кнопка 📹, оверлей с локальным/удалённым видео,
  mute/cam/end, STUN Google.
- **Android** (`call/CallActivity.kt`, `call/SignalingClient.kt`):
  `org.webrtc`, входящие и исходящие звонки, кнопка 📹 в чате,
  перехват входящего offer в `MainActivity`.
- Для строгих NAT нужен TURN-сервер (сейчас только STUN).

## E2E-шифрование (сделано, базовый уровень)

ECDH P-256 + AES-256-GCM, совместимо веб ↔ Android:

- Реестр публичных ключей: `POST /keys`, `GET /keys/{ss_id}` (SPKI DER).
- **Веб** (`index.html`): прозрачное шифрование — если у получателя есть
  ключ, тело шифруется; иначе открытый текст (фолбэк). Конверты
  `{enc:1,n,c}` расшифровываются при приёме.
- **Android** (`crypto/CryptoBox.kt`): тот же формат (готов к интеграции
  в поток сообщений `ApiService`/`ChatActivity`).

**Ограничение:** реестр ключей без аутентификации (система анонимная) —
защита от пассивного чтения (дамп БД, снифинг на хопе), но не от
активного MITM. Закрывается подписью конвертов (см. ниже).

## Безопасность (сделано)

- Энтропия SSID 16 → 32 бита, лимиты длины текста/SSID.
- Rate limiting: `/register` 10/мин, `/message` 60/мин, `/upload`
  20/мин на IP → 429.
- XSS в веб-UI (URL вложения) закрыт экранированием.
- Опциональный pymongo не валит ноду при импорте.

## Дорожная карта (осталось)

1. **Подпись конвертов** (ed25519): подписывать `msg_id`/`path`/тело,
   чтобы закрыть активный MITM и спуфинг в реестре ключей. Поле `sig`.
2. **Интеграция CryptoBox в поток Android-сообщений** (шифровать в
   `ChatActivity`/`ApiService`, публиковать ключ при регистрации).
3. **Персистентные BLE-соединения и очередь записи** вместо
   connect-write-disconnect на каждое сообщение.
4. **Перевод Android-отправки/приёма на `MeshManager`** (сейчас идёт
   через `ApiService` напрямую) + индикатор активных транспортов и
   запрос рантайм-разрешений BLE/Wi-Fi.
5. **Foreground-сервис** для фонового реле (BLE advertise/scan).
6. **TURN-сервер** для видеозвонков за строгими NAT.
7. **TLS/HTTPS + certificate pinning**, убрать `usesCleartextTraffic`
   для release.
8. **Тесты Android** (Robolectric для `ChunkAssembler`/`CryptoBox`).
